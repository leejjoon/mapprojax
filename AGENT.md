# AGENT.md

This file provides guidance to coding agents working with code in this repository.

mapprojax implements FITS WCS map projections (the zenithal TAN, SIN, ZEA, STG and ARC, plus SIP distortion) as differentiable JAX PyTrees, partly ported from [cds-mapproj-rust](https://github.com/cds-astro/cds-mapproj-rust). Its distinguishing feature is a precision strategy that keeps fp64 off the per-pixel path. The downstream image-reprojection package is **reprojax** (separate repo, `../reprojax`), which builds on mapprojax's `Reprojector`. Version 0.4.0 is tested with reprojax 0.3.0, which declares `mapprojax[astropy]>=0.4.0,<0.5` (the historical 0.3.0 pairing was reprojax 0.2.0, `mapprojax>=0.3.0,<0.4`).

## Commands

The environment is managed with uv (Python 3.12, `.venv/`).

```bash
uv sync --extra test                 # pytest + astropy
uv sync --extra test --extra rocm    # also the AMD ROCm 7 JAX plugin (pins jax==0.11.1)
uv run pytest                        # full suite (testpaths = tests)
uv run pytest tests/test_sip.py::test_name -q   # single test
uv run python benchmarks/benchmark_accuracy.py --markdown docs/benchmarks/accuracy_results.md  # accuracy vs astropy; exits non-zero on regression
uv run python benchmarks/benchmark_precision.py # also benchmark.py, benchmark_optimization.py, benchmark_sip.py
```

- `tests/verify_jax.py` is a standalone script, not collected by pytest.
- Tests that need x64 enable it themselves through autouse fixtures that save and restore `jax.config.jax_enable_x64`. Don't assume a global setting.
- Run the suite on both backends before calling a change done: `JAX_PLATFORMS=cpu` and `JAX_PLATFORMS=rocm XLA_PYTHON_CLIENT_PREALLOCATE=false`. On the shared-memory Strix Halo APU, preallocation slows NumPy in the same process 3–5×.
- **Accuracy report.** `docs/benchmarks/accuracy_results.md` is generated by `benchmark_accuracy.py`. Never edit it by hand. Regenerate it and review the diff.
- **Timing gate.** `benchmarks/benchmark_stage3.py` (subprocess workers; warm, lowering, compile and cold) and `benchmarks/compare_stage3.py BASELINE CANDIDATE ...` (exits 1 if a rule fails).
  - The legacy classes are gone, so take a baseline from a `git archive` of an older commit, run there with `PYTHONPATH=<dir>/src`, in the same session as the candidate.
  - Files under `benchmarks/results/` are frozen evidence. Add new files; never rewrite old ones. `benchmarks/results/stage3-closure.md` indexes the canonical sets.

## Architecture

### Pipeline and frames

Every WCS runs the same pipeline (`_PipelineBase` in `src/mapprojax/base.py`):

```
pixel ─(−crpix, SIP pix_to_foc)→ (u,v) ─(CD, degrees)→ plane (X,Y) ─(projection)→ native unit vector ─(r_matrix)→ celestial unit vector ─→ (lon, lat)
```

- `pix_to_native` / `native_to_pix` cover everything except the celestial rotation; `proj_xyz` / `unproj_xyz` add the rotation; `proj` / `unproj` add the spherical↔Cartesian step.
- The native frame puts the projection's reference point at unit vector (1, 0, 0) with native north up (`utils.rotation_matrix`). Projection formulas in `projections.py` are written against that convention, as in cds-mapproj: e.g. TAN is `X = y/x, Y = z/x`.
- **Validity.** Every stage has a `_..._valid` form returning finite values plus a validity flag. Invalid samples carry a safe stand-in, and NaN is inserted only at the public output. Inserting NaN earlier poisons parameter gradients (`0 * NaN`) even when the caller masks the sample. Preserve this when adding steps.
- **Conventions.** `crpix` is 0-based (`wcs_utils.load_wcs_params_from_header` subtracts 1 from FITS CRPIX). `crval` and `cd` are in degrees. `proj` / `unproj` take and return radians in (lon, lat) order.
- **SIP inverse.** `Sip.foc_to_pix` uses AP/BP only as the initial guess, Newton-solves against A/B for `inverse_steps` steps, and marks unconverged points invalid.

### Classes

- **Public classes.** `Tan`, `Sin`, `Zea`, `Stg` and `Arc` (`wcs.py`) are a projection mixin (`projections.py`: `TanMixin`, `SinMixin`, `ZeaMixin`, `StgMixin`, `ArcMixin`, supplying `_native_to_plane` / `_plane_to_native`) plus `_PrecisionWCSBase(_PipelineBase)`. All are registered as PyTrees.
- **Precision.** It is a required keyword: `precision="f32" | "mixed" | "f64"`. It is aux data, as is SIP `inverse_steps`, which is static and changes the compiled program.
- **Leaves.** The leaves are `crpix`, `cd`, `crval` and the SIP coefficients. `r_matrix` is derived on access and never stored.
- **Reconstruction.** `tree_unflatten` rebuilds through `__new__` and only assigns, so `tree_map` casts and `jax.eval_shape` survive. Never route unflatten through `__init__`.
- **`crval` storage.** It is stored as given (`_normalize_crval`); a NumPy float64 reference stays a host fp64 array. A sequence mixing float precisions is rejected rather than promoted.
- **Batching.** There are no `*Array` classes: stack compatible PyTrees and use `jax.vmap` (recipes in the `wcs.py` module docstring and the user manual). The constructor also accepts batched leaves, which reprojax uses.
- **Adding a projection** touches `projections.py` (the mixin), `wcs.py` (the class), `__init__.py`, `_SUPPORTED_PROJECTIONS` in `wcs_utils.py`, the dispatch in `astropy.py`, and the class lists in the tests and `tests/accuracy_reference.py`. Read the `projections.py` module docstring first: every branch, including the unselected side of a `where`, must stay finite, and invalid samples' stand-ins land on the reference point (native `(1, 0, 0)`, plane `(0, 0)`), so any removable singularity there needs a series (see `ArcMixin`). `tests/test_zenithal.py` is the template for the projection-specific tests.
- `jax_base.py` holds only the x64 guards (`_require_x64`, `_effective_f64`) and the `Sip` PyTree registration.

### Precision strategy

Read DEVELOPER.md and `docs/benchmarks/accuracy_results.md` before touching numerics.

- **Where fp64 is needed.** The only step that needs fp64 is the celestial↔native rotation, where O(1) unit-vector products cancel into field-sized offsets. Everything else is fine in fp32.
- **Modes.**
  - `f32`: everything in fp32. There is no `proj` / `unproj`; use the offset path.
  - `mixed`: fp32 pipeline, fp64 `crval` and rotation, with casts at both rotation boundaries.
  - `f64`: fp64 throughout.

  Mixed and f64 require x64 and raise clearly without it.
- **Offset path.** `unproj_offset` / `proj_offset` work in small offsets from CRVAL `(Δlon·cos lat0, Δlat)`, so they stay accurate in fp32. `offset_scale()` returns the producer's typed cosine. The host helpers `absolute_from_offset(offset, *, crval, offset_scale)` and `offset_from_absolute(absolute, *, crval, offset_scale)` (`base.py`) add the O(1) fp64 epilogue on the host and divide by that same rounded scale. Never recompute the cosine; that is catastrophic near the poles. The helpers reject tracers.
- **`Reprojector`** (`reproject.py`) maps pixels in one WCS to pixels in another without fp64 per pixel.
  - `Reprojector(src, tgt, frame_rotation=None, matrix_precision="f32")` composes the native(src)→native(tgt) matrix once on the host in NumPy fp64, through `utils.compose_relative_rotation`. That needs a concrete float64 `crval`. After a transformation that truncated or traced `crval`, pass retained originals via `compose_relative_rotation(..., crval_src=, crval_tgt=)`.
  - `Reprojector.from_matrix(src, tgt, m_rel)` takes the matrix as a JAX leaf, so gradients flow through `m_rel`. reprojax's differentiable path uses it.
  - The legs are `wcs.with_precision(matrix_precision)` copies. Any object with `with_precision` and the `_pix_to_native_valid` / `_native_to_pix_valid` protocol conforms.
- **Guards worth keeping.**
  - The f32 `Reprojector` jaxpr must contain no f64 operation; `tests/test_x64_policy.py` walks nested jaxprs.
  - Changing only numerical leaves must not retrace; there is a trace-count test in `tests/test_wcs_new.py`.
  - Gradients are checked per mode with scale-aware tolerances in `tests/test_gradients_modes.py`.

### Serialization

`to_dict` / `from_dict` (JSON) is the only format. It records the type, precision, `crval_dtype` and SIP, including `inverse_steps`. It rejects a mismatched class and the old untyped format (`tests/test_wcs_json.py`). ASDF support was removed in 0.3.0.

## Current direction

`docs/plan/mapprojax improvement plan.md` is the agreed roadmap and supersedes the plan sections of DEVELOPER.md and `fo64_report_and_plan.md`. Stages 1–3 are complete. Stage 3, the JAX-first restructure, closed on Nov 4 2026 with the verified pair mapprojax `10f9c75` / reprojax `5fadcf7`. Stages 4, 5 and 6 have since closed: 0.4.0 is on PyPI, and reprojax 0.3.0 (its first trusted-publisher release, with attestations) closed Stage 6 on Nov 16 2026. See the plan's Stage 6 closure section. Milestone v0.5.0 (ZEA, STG, ARC; plan section of that name) is in progress. Check the plan before starting work.

- **Scope.** Image resampling (interpolation, flux, tiling, coadds) belongs in reprojax, not here.
- **API changes are breaking.** There are no compatibility aliases. Update the migration table in `docs/user_manual.md` and check reprojax against the change, running its suite with `PYTHONPATH` pointing at this tree.
- **No releases or pushes** without an explicit instruction.

## Repo hygiene

The repo root has untracked scratch files: FITS images (`1904-66_*.fits`, `reprojected_*.fits`), `t.tgz` (92 MB), `reproj_test/`, ad-hoc scripts (`debug_coords.py`, `ex_proj*.py`, `test_precision.py`), and notes (`docs/FITS WCS Relation Note.md`, `docs/sip/shupeADASS.pdf`). `CLAUDE.md` (a one-line pointer to this file) and `AGENT.md` are tracked. `benchmarks/results/stage3-g012-qa.json` is a withdrawn QA report, and the 26 `benchmarks/results/stage4-*.json` files without the `-r2` suffix are a superseded timing set (`benchmarks/results/stage4-closure.md:50`); both stay untracked. `.gjc/` (GJC session state) and `.gjc-out/` (Stage 1–4 QA output) are excluded locally through `.git/info/exclude`, not `.gitignore`. Stage 6's release evidence is kept outside the repo, in `~/archive/mapprojax-stage6-evidence/`. Some of these *are* gitignored — `*.fits` and `*.tgz` (`.gitignore:154-155`), so the FITS images and `t.tgz` are silent; everything else is not, which is why `git add .` is still the wrong move. Stage files explicitly.
