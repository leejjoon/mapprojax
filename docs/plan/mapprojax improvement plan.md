# mapprojax improvement plan

Nov 1, 2026 · @이재준 · revised after a two-reviewer committee review (Claude Opus 5.5, Codex gpt-5.6-sol) of the Oct 31 draft

## Where it stands

mapprojax v0.2.0 is a ~1,200-line WCS core: two projections (TAN, SIN), SIP distortion, NumPy and JAX classes built from shared mixins, PyTree registration, the fp64-free `Reprojector`, and the offset-form `unproj_offset`/`proj_offset` APIs. 89 tests pass. It has no README, no CI, no release, and 0 stars.

The Oct 31 draft overstated two things and missed several bugs:

- **Precision.** "fp64-grade astrometry at fp32 cost" rests on a 200×200 round trip (7.6e-6 px). At realistic image sizes the measured errors are 1.9e-3 px for JAX Mixed and 2.6e-3 px for `Reprojector` f32, up to 8.4e-3 px for a cross-field pair at 0.05″/px (`docs/benchmarks/precision_results.md`). An fp32 pixel coordinate near 4096 has a spacing of 4.9e-4 px, so no fp32 path can reach the round-trip figure in absolute terms. The `reproject.py` docstring (~1e-4 px) and DEVELOPER.md (1e-3 to 1e-2 px) disagree with each other and with the measurements.
- **Correctness.** Four bugs return wrong answers or crash today; see Stage 2. The self-round-trip tests in `tests/test_projections.py` cannot catch them.

## Decisions

1. **mapprojax is JAX-first.** One class per projection, registered as a JAX PyTree. NumPy stays only where fp64 must live on the host: `crval` and the composition of the celestial↔native rotation. The NumPy `Tan`/`Sin` classes, the `*Array` variants (replaced by `vmap`), the `*Mixed` variants (precision becomes a static field) and the private per-projection reprojection legs all go. There is no PyPI release and the only downstream is reprojax, so the API break is cheapest now; no backward-compatibility aliases.
2. **mapprojax is the coordinate kernel; reprojax is the image tool.** mapprojax owns projections, distortions, rotations, precision policy and the source-pixel map with its validity mask. reprojax owns interpolation, flux handling, tiling and coadds. The Oct 31 draft's Phase 4 moves to reprojax.
3. **Compete on the precision design, not on projection count.** jax-galsim `GSFitsWCS` already covers TAN/TPV/TNX/SIP/STG/ZEA/ARC with iterative inversion. mapprojax's distinct contribution is the measured fp32/fp64 envelope, the offset form, and the fp64-free `Reprojector`. Add projections when real data asks for them.
4. **State numbers that survive scrutiny.** Lead with realistic-size errors (~2e-3 px at fp32, ~1e-11 px at fp64) and the plate-scale envelope, not the round-trip figure. Drop "fp64-grade".

## Milestone v0.3.0: a coordinate kernel you can trust

The stages are ordered so each one protects the next. The validation suite comes first because it is the safety net for the fixes and the restructure.

### Stage 1: independent validation

- [x] Compare TAN, SIN and TAN-SIP against `astropy.wcs` (`all_pix2world` / `all_world2pix`) over dense grids. Replace self-round-trips as the main correctness check.
- [x] Cover the edge cases: back hemisphere and the boundary of each projection's valid region, near-pole fields, RA wrap at 0/360, and SIP headers with A/B but no AP/BP. Seed with the wcslib `1904-66_*.fits` test headers.
- [x] Validate the real SPHEREx pair end to end against astropy: the L2 source exposure (`reproj_test/level2_…v20.fits`, HDU 1, `RA---TAN-SIP`, order-3 A/B and AP/BP, 2040², 5.7″/px) onto the GLON-TAN template (`reproj_test/template.fits`, 1201², 6″/px). Build the ICRS→Galactic `frame_rotation` in fp64 from astropy rather than typing it in; today `frame_rotation` is tested only with a synthetic z-rotation (`tests/test_reproject_relative.py:210-234`). Move `reproj_test/test_wcs_consistency.py` into `tests/` as the seed.
- [x] Minimal gradient smoke test: one fp64 `check_grads` case on `TanJax` with respect to `crpix`, `cd`, `crval` and SIP `a`/`b`, at interior points. It is the safety net for Stage 3, which rewrites the gradient surface; the full matrix stays in Stage 4.
- [x] Publish the max and RMS disagreement (mas and px) as a table in `docs/`, generated by a script so it can be regenerated.

### Stage 2: correctness fixes

Commit these before the restructure so they do not wait on it.

- [ ] **Projection domains.** TAN maps a point 179.99° from the reference to a mirrored valid pixel; SIN folds the back hemisphere onto the front (`projections.py:6`, `:19`). Return NaN where `xn <= 0` (TAN) and `xn < 0` (SIN), written with a double-`where` so gradients stay finite. Contract: the coordinate functions (`proj`, `unproj`, `pix_to_pix`, …) return NaN for invalid positions; the separate boolean mask comes from the Stage 4 pixel map. `tests/test_wcs_regressions.py` asserts non-finite output, not specifically NaN.
- [ ] **SIP inverse.** With A/B and no AP/BP, `foc_to_pix` silently applies zero correction (`sip.py:31-32`); the measured round-trip error was 1.6 px. Upstream reprojax's `_sip_refine.py` (AP/BP initial guess + fixed Gauss-Newton steps) and harden it: start from AP/BP when present and from the identity otherwise, use the exact A/B solve automatically when AP/BP is absent, and return the residual or a convergence flag. Differentiate through the unrolled iterations; use implicit (`custom_jvp`) gradients only together with a residual check, since they are only valid at a converged root.
- [ ] **SIP evaluation by Horner's rule.** `_evaluate_poly` builds `u[..., None] ** p_range` power arrays (`sip.py:54`). At 1201², order 4, the broadcast form takes 498 ms in NumPy eager mode and 5.7 ms (CPU) / 0.8 ms (GPU) under `jit`; Horner takes 8.4 ms eager and 0.16 / 0.11 ms under `jit`, with the same accuracy. The SIP inverse rewrite touches the same code, so do both together, and commit the benchmark to `benchmarks/`.
- [ ] **PyTree reconstruction.** `tree_unflatten` must not call `__init__` (`jax_base.py:34`, `:48`). Today it recasts dtypes, rebuilds the rotation matrix on every unflatten, and crashes on non-array leaves (`jax.eval_shape(lambda w: w, wcs)` raises `TypeError`). `Reprojector` already uses the `__new__` pattern (`reproject.py:217-222`). Doing this here, not in Stage 3, means it survives the factory fallback. Add regression tests for `jit`, `vmap`, `grad`, `eval_shape` and dtype preservation.
- [ ] **Singular or non-finite CD.** The `try/except LinAlgError` in `native_to_pix` (`base.py:43`) only works for NumPy; `jnp.linalg.inv` never raises and returns NaN/Inf, eagerly or under `jit`. Check `det(cd) != 0` and finiteness at construction when the values are concrete; document NaN output for traced parameters.
- [ ] **Header checks.** `wcs_utils.load_wcs_params_from_header` ignores `CTYPE`, so it silently accepts GLON, CAR or anything else as TAN. Accept only TAN/SIN (with or without `-SIP`) in either equatorial or galactic axes, and refuse a non-default `LONPOLE` rather than ignoring it: a non-default value changes TAN and SIN too. `LATPOLE` has no effect for zenithal projections (`tests/test_wcs_utils.py:116`), so it is accepted.
- [ ] **Near-pole declination.** `utils.xyz_to_radec` computes `dec = arcsin(z)`, which is ill-conditioned near the pole: fields at dec ±89.9 miss astropy by 1.5–2.0e-4 mas through `unproj` (the 1e-4 mas budget), while `unproj_absolute` on the same fields stays within 1.9e-7 mas. Use `atan2(z, hypot(x, y))`; it flips the 8 strict `xfail`s in `tests/test_astropy_reference.py`.
- [ ] **x64 warning.** The import-time warning (`__init__.py:4-10`) fires for `Reprojector` f32 and offset users, who do not need x64. Remove it; warn or raise only when a path that needs fp64 (e.g. `matrix_precision="f64"`) is requested with x64 off.

### Stage 3: JAX-first restructure

Timebox this stage. If it overruns, ship v0.3.0 with a small internal factory that generates the existing classes from each mixin, keep the public names, and mark the API unstable before 1.0.

- [ ] One class per projection, using `jax.tree_util.register_dataclass` (no equinox/flax dependency). Precision mode is a static field; per-pixel work runs in fp32 or fp64 accordingly.
- [ ] Keep `crval` and rotation composition as an explicit host-side fp64 step (NumPy), separate from the device kernel, for the reprojection and offset paths. Also keep a traced rotation path built from `crval` inside JAX, so the `crval` gradients that work today in fp64 `TanJax` survive for fitting. Replace `unproj_absolute`'s NumPy-only restriction with a free function such as `absolute_from_offset(offset, crval_f64)`.
- [ ] Derive the inverse CD matrix inside the trace (closed-form 2×2), replacing `jnp.linalg.inv` and the `try/except`. Do not store `cd_inv` as an independent leaf, which would break gradients with respect to `cd`.
- [ ] Replace `*Array` classes with documented `vmap` usage; let `Reprojector` take any projection without a private leg subclass.
- [ ] Serialization: keep `to_dict`/`from_dict` (JSON, tested). Remove the ASDF converter until it handles SIP and the new classes; it currently drops SIP, registers only NumPy classes and has no tests.
- [ ] Update reprojax to the new API in the same pass.

### Stage 4: the kernel's public surface

- [ ] **Pixel map with validity mask.** Given a target shape and the source image shape, `Reprojector` returns source pixel coordinates plus a mask combining the projection domain and the source footprint. Define the pixel-edge convention explicitly (a pixel centre at index `i` covers `[i-0.5, i+0.5)`). Every resampler needs this and only mapprojax knows the domains; coverage that depends on the interpolation kernel stays in reprojax.
- [ ] **Gradient tests.** `jax.test_util.check_grads` with respect to `crpix`, `cd`, `crval` and SIP `a`/`b`, for each projection, at several field positions, in fp64 first and then with documented fp32 tolerances. A package sold as differentiable must verify this before release.
- [ ] **Differentiability table.** Which parameters are differentiable in which precision mode, including `Reprojector`'s host-side `crval` composition.

### Stage 5: docs and release

- [ ] Reconcile the precision numbers across the `reproject.py` docstring, DEVELOPER.md and `precision_results.md`, using realistic-size figures. Link the existing plate-scale envelope tables rather than producing new ones.
- [ ] Fix `docs/user_manual.md`: remove the nonexistent `to_bytes`/`from_bytes`, remove the ASDF recommendation, and rewrite examples for the JAX-first API.
- [ ] README built from `user_manual.md` and the DEVELOPER.md decision tree: what mapprojax is (coordinate kernel), what it is not (header parsing and general pix↔sky stay in astropy; image resampling is reprojax), the precision table, and the comparison with jax-galsim, dfreproject and astropy `reproject`. `pyproject.toml` already points at the missing README.
- [ ] State conventions once: 0-based pixels, `crval` in degrees, `proj`/`unproj` in radians, (lon, lat) order, and behaviour outside each projection's domain.
- [ ] Mark `fo64_report_and_plan.md` as implemented (its header still says "not started") and move it and `GEMINI.md` into `docs/notes/`. Add `*.fits` and `*.tgz` to `.gitignore` and clean scratch scripts out of the root.
- [ ] Rerun `benchmark_precision.py` on Strix Halo: the committed results predate the script's rewrite and lack the `Reprojector` columns and accuracy section.
- [ ] CI on GitHub Actions: one full job with x64 on, plus a separate-process x64-off smoke job covering import without warning, `Reprojector` f32, the offset APIs and no fp64 in the jaxpr. The tests toggle x64 themselves, so a full on/off matrix would mostly fail for expected reasons.
- [ ] Packaging: set `requires-python` and the JAX floor to what CI tests (the rocm extra already needs Python 3.12); add LICENSE; verify a clean wheel install.
- [ ] GitHub description and topics; tag v0.3.0; publish to PyPI.

## After v0.3.0

| Item | Why | Notes |
| --- | --- | --- |
| `from_astropy(wcs)` | Lets users and reprojax pass astropy WCS objects directly | Accept TAN/SIN(+SIP), normalise CD/PC+CDELT through astropy, refuse everything else clearly. `to_header` later |
| TPV | Standard in SCAMP/SWarp output (DES, DECaLS, Pan-STARRS) | A distortion step like SIP, so no new projection class; shares the Newton inverse from Stage 2. Watch the radial terms' non-differentiable `r` at the origin |
| Astrometric-fit example | The demo for the gradient story | Fit CD + SIP to Gaia matches; compare with `astropy.wcs.utils.fit_wcs_from_points` |
| ZEA, STG, ARC | Zenithal family, cheap once the restructure is done | Add when a dataset needs them |
| `Reprojector` differentiable in `crval` | Closes the last gradient gap | The rotation is composed on the host today |
| Research note | Makes the precision work citable | RNAAS length, built on realistic-size numbers. The contribution is the measured envelope and the offset form; composing M_tgt·M_srcᵀ itself is standard |

## Cut or deferred

- **Image resampling in mapprojax** (`reproject_interp`, flux-conserving variant, tiling, coadd): belongs in reprojax. When it is built there, note that JAX `map_coordinates` supports only order 0 and 1, and that Jacobian-scaled interpolation is not flux-conserving under downsampling (use adaptive anti-aliasing or drizzle).
- **Array-API backend inference and PyTorch/CuPy support**: works against the host-fp64 / device-fp32 split; dfreproject already serves PyTorch users.
- **equinox / flax**: `register_dataclass` covers the need without a dependency.
- **CAR, AIT, MOL**: needed only for all-sky maps, an audience not targeted yet.
- **Non-default LONPOLE**: the default is already encoded for zenithal projections and is what the SPHEREx template uses (`LONPOLE` 180 at δ₀ = 0.48°). Until then, refuse non-default `LONPOLE` (Stage 2); `LATPOLE` has no effect for zenithal projections and is accepted. General support must reproduce WCSLIB's defaults and ambiguity rules, not just a three-angle rotation.
- **`-TAB`, D2IM lookup distortions**: defer unless a user asks.

## Risks

- **Bus factor of one.** Let the SPHEREx workload through reprojax set priorities rather than hypothetical users.
- **The restructure can stall the release.** Mitigated by the timebox and the factory fallback in Stage 3.
- **Precision claims are the trust signal.** Every number in the README must trace to a script in `benchmarks/` that a reader can rerun. Timing claims must name the backend and say whether they were measured under `jit`.

So the diagnosis is right: the problem is verification and plumbing, not the projection
math. Retracting "fp64-grade" and leading with 2e-3 px instead of the 200×200 round-trip
is the correct call, and Stage 1 before everything else is the right order — round-trip
tests only prove self-consistency, which is exactly how a mirrored TAN slipped through.

### Requested changes

**1. Promote SIP Horner evaluation from "Cut or deferred" to Stage 2.** The gradient
half of the deferral argument is correct and I confirmed it (`d/du` at `u=0` → 0.0,
finite; `u**0` contributes nothing). The cost half is not. `_evaluate_poly` broadcasts
`u[..., None] ** p_range`, materialising order² full-frame temporaries:

| Order-4 SIP, 1201×1201 (real frame size) | ms |
| --- | --- |
| polynomial, broadcast (current) | 498 |
| polynomial, Horner | 8.4 |
| `native_to_pix`, no SIP | 13.7 |
| `native_to_pix`, with SIP | 1017 |

59× on the polynomial; at 4096² it is 5.8 s vs 0.31 s with ~1.5 GB peak allocation.
One SIP evaluation costs 75× the rest of the transform, so SIP is not a rounding error on
the kernel's usefulness — it is the kernel. Max deviation between the two forms is 5e-7.
This belongs with the SIP inverse work, which rewrites the same code path anyway.

**2. Move the gradient smoke test from Stage 4 to Stage 1.** Stage 3 rewrites the PyTree,
the `cd_inv` leaf and the `*Array` path — all gradient surface — and its verification
currently lands one stage later. `crval` gradients do work today in fp64 `TanJax`
(finite, non-zero), so a minimal `check_grads` case next to the astropy harness costs a
few lines and becomes Stage 3's safety net. Keep the full matrix in Stage 4.

**3. Add singular-CD behaviour to Stage 2.** `native_to_pix` wraps `linalg.inv` in
`try/except LinAlgError`, which raises `ValueError` eagerly but, inside `jax.jit`, cannot
see the error and returns `nan` silently. Same code, two behaviours. One test line.

### Context for prioritisation

The Risks section says to let the SPHEREx workload set priorities. The real
`reproj_test/template.fits` is `GLON-TAN`, 1201×1201, `CDELT` 6e-3° (6″/px), `CRVAL`
(78.93, 0.48), `LONPOLE` 180, and **carries no SIP keys**. So SIP is not what SPHEREx
needs today — but it is the thing that makes the kernel unusable the day it appears, which
is why item 1 is not a "wait for profiling" deferral.

### Committee response — Nov 1 2026

Both reviewers (Claude Opus 5.5, Codex gpt-5.6-sol) agreed with all three requested changes; they are folded into Stages 1 and 2 above. Corrections and additions:

- **SIP is on the SPHEREx hot path today.** The template has no SIP, but the source L2 exposure is `RA---TAN-SIP` with order-3 A/B and AP/BP (also in `reproj_test/wcs_test_data.json:28`). Reprojection maps target pixels to source pixels, so every pixel goes through the source's AP/BP inverse, and through the ICRS→Galactic `frame_rotation`. - **Singular CD is wrong in both JAX modes**, not only under `jit`: `jnp.linalg.inv` never raises.
- **There is no `cd_inv` leaf today**; the inverse is computed inside `native_to_pix`.
- **Added beyond the review:** a `CTYPE`/`LONPOLE` check in the header loader, the PyTree fix moved into Stage 2 so it survives the factory fallback, a traced `crval` path kept for fitting, the source shape and pixel-edge convention for the validity mask, and the real SPHEREx pair as a Stage 1 fixture.

### Committee response to the Stage 1 preflight — Nov 1 2026

Both reviewers (Claude Opus 5.5, Codex gpt-5.6-sol) checked the preflight against the repo. Claude also ran the real SPHEREx pair end to end. They agree with its direction (Stage 1 is mostly harness work over forward math that already matches astropy) but correct D1–D3 and the order.

**D1 — fixtures: commit header-only text, never fetch at test time.**

- Coordinate tests need headers, not pixels. Copy astropy's `1904-66_TAN.hdr` / `1904-66_SIN.hdr` (≈9 KB, from `astropy/wcs/tests/data/maps/`) into `tests/data/`, and extract the SPHEREx L2 header (≈20 KB) and template header (≈2.9 KB) as text fixtures, recording each file's provenance. The FITS files carry 72 MB + 29 MB of unused pixel data.
- Keep `*.fits` ignored without exceptions. The premise that the fixtures "are about to be deleted" is also wrong: `.gitignore` does not delete files and does not affect tracked ones.
- No network at test time: CI may have none, and the L2 file has no stable URL. Large-image downloads, if ever needed, belong in optional reprojax integration tests with pinned URLs and checksums.
- The SIN header carries `PV2_1 = PV2_2 = 0`, which mapprojax ignores. The loader should assert they are zero and refuse non-zero `PV`.

**D2 — the JSON is already tracked and tested.** `reproj_test/wcs_test_data.json` is in git and consumed by `tests/test_wcs_json.py:13-26` through `load_wcs_params_from_header`, with a `pytest.skip` if absent. It is a different SPHEREx field (CRVAL 306.77, 39.38), so it is a genuine third header, though its saved astropy output is not an independent implementation. Move it to `tests/data/`, resolve paths relative to the test file, and fail instead of skipping when a fixture is missing. Dropping `test_wcs_consistency.py` is agreed.

**D3 — the frame rotation is correct; the real-pair residual is the SIP inverse.**

- Claude's measurement: `Reprojector` (f64) with an astropy-derived Galactic→ICRS matrix matches astropy's chain (template pixel → Galactic → ICRS → L2 pixel) to 6.2e-3 px max; f32 gives 6.3e-3 px. The transposed matrix is off by ~1e5 px, so a direction error cannot hide.
- The 6e-3 px floor is the AP/BP approximation against astropy's iterative `all_world2pix`. So the end-to-end test will fail for a Stage 2 reason, not a frame reason. Set its tolerance to the measured AP/BP floor (~7e-3 px) now, tighten it once the Newton inverse lands, and add the transposed-matrix case as a negative test.
- Sampling a Galactic target from an equatorial source uses the inverse of ICRS→Galactic; state the direction in the test and validate both directions.
- "Only genuinely new work" understates the rest. The existing inverse assertions allow 0.05 px (`tests/test_wcs_json.py:115`), and the missing-AP/BP, back-hemisphere and gradient checks are real validation.

**"Mostly confirm" — true for the forward math only.** `1904-66_TAN` agrees with astropy to 2e-7 mas, including `unproj_absolute` at CRVAL2 = −90. Expect failures from the SIP inverse and the projection domains. Dense grids of valid pixels will not expose back-hemisphere defects, so add explicit sky→pixel cases there.
