# mapprojax improvement plan

Nov 1, 2026 · @이재준 · revised after a two-reviewer committee review (Claude Opus 5.5, Codex gpt-5.6-sol) of the Oct 31 draft

## Where it stands

mapprojax v0.2.0 is a ~1,200-line WCS core: two projections (TAN, SIN), SIP distortion, NumPy and JAX classes built from shared mixins, PyTree registration, the fp64-free `Reprojector`, and the offset-form `unproj_offset`/`proj_offset` APIs. 89 tests pass. It has no README, no CI, no release, and 0 stars.

The Oct 31 draft overstated two things and missed several bugs:

- **Precision.** "fp64-grade astrometry at fp32 cost" rests on a 200×200 round trip (7.6e-6 px). At realistic image sizes the measured errors are 1.9e-3 px for JAX Mixed and 2.6e-3 px for `Reprojector` f32, up to 8.4e-3 px for a cross-field pair at 0.05″/px (`docs/benchmarks/precision_results.md`). An fp32 pixel coordinate near 4096 has a spacing of 4.9e-4 px, so no fp32 path can reach the round-trip figure in absolute terms. The `reproject.py` docstring (~1e-4 px) and DEVELOPER.md (1e-3 to 1e-2 px) disagree with each other and with the measurements.
- **Correctness.** Four bugs return wrong answers or crash today; see Stage 2. The self-round-trip tests in `tests/test_projections.py` cannot catch them.

## Decisions

1. **mapprojax is JAX-first.** One class per projection, registered as a JAX PyTree. NumPy stays only where fp64 must live on the host: `crval` and the composition of the celestial↔native rotation. The NumPy `Tan`/`Sin` classes, the `*Array` variants (replaced by `vmap`), the `*Mixed` variants (precision becomes a static field) and the private per-projection reprojection legs all go. There is no PyPI release and the only downstream is reprojax, so the API break is cheapest now; no backward-compatibility aliases.
2. **mapprojax is the coordinate kernel; reprojax is the image tool.** mapprojax owns projections, distortions, rotations, precision policy and the source-pixel map with its validity mask. reprojax owns interpolation, flux handling, tiling and coadds. The Oct 31 draft's Phase 4 moves to reprojax.
3. **Compete on the precision design, not on projection count.** jax-galsim `GSFitsWCS` already covers TAN/TPV/TNX/SIP/STG/ZEA/ARC with iterative inversion. mapprojax's distinct contribution is the measured fp32/fp64 envelope, the offset form, and the fp64-free `Reprojector`. Add projections when real data asks for them.
4. **State numbers that survive scrutiny.** Lead with realistic-size errors (~2e-3 px at fp32, ~1e-11 px at fp64) and the plate-scale envelope, not the round-trip figure. Drop "fp64-grade".

## Milestone v0.3.0: a coordinate kernel you can trust

The stages are ordered so each one protects the next. The validation suite comes first because it is the safety net for the fixes and the restructure.

## Cut or deferred

- **Image resampling in mapprojax** (`reproject_interp`, flux-conserving variant, tiling, coadd): belongs in reprojax. When it is built there, note that JAX `map_coordinates` supports only order 0 and 1, and that Jacobian-scaled interpolation is not flux-conserving under downsampling (use adaptive anti-aliasing or drizzle).
- **Array-API backend inference and PyTorch/CuPy support**: works against the host-fp64 / device-fp32 split; dfreproject already serves PyTorch users.
- **equinox / flax**: `register_dataclass` covers the need without a dependency.

**What changed from the previous Stage 2 text, and why**

- **The SIP inverse always refines.** The old wording used the exact A/B solve only when AP/BP was absent. Four of the five SIP `xfail`s concern AP/BP that is present but approximate, so that rule would have left them failing.
- **The solver is a focal-plane 2×2 Newton step, not a copy of `_sip_refine.py`.** The reprojax code uses `jax.jacfwd`/`vmap` on a damped 3×2 system in native space, so it cannot serve the NumPy classes that own three of the `xfail`s. Fable's prototype converged in two steps.
- **Domain masking reaches through the pipeline.** Fable first proposed masking only in `_native_to_plane`. Astra showed, and Fable reproduced, that the NaN then poisons the `cd` gradient through the CD multiply even under a masked loss. SIN's unguarded inverse `sqrt` fails the same way through `crval`.
- **Traced invalid CD needs output masking.** "Skip tracers and document NaN" was not enough: Astra reproduced finite, wrong outputs for a traced `inf` and a traced singular CD.
- **The closed-form 2×2 inverse moves from Stage 3 into Stage 2.** The traced mask needs the determinant inside the trace anyway (Fable's argument; Astra conceded).
- **The PyTree fix moves first.** CD validation must never run during unflatten, which also rebuilds gradient objects with possibly singular CD leaves (Astra's argument; Fable conceded). `r_matrix` becomes a derived property: storing it as a leaf would silently zero `crval` gradients.
- **Header checks grew.** Both found that `CRVAL2 = +90` without `LONPOLE` is wrong (WCSLIB default 0, current behaviour 180; 435–1000″ against astropy). Astra found the off-diagonal-only CD parsed as the identity. Fable added `CUNIT` and `CROTA2`.
- **Horner is its own pure-refactor commit** (Fable's argument; Astra conceded), benchmarked with Astra's methodology.
- **Convergence is enforced, not only reported.** Astra's position, unopposed: `inverse_residual` is used internally so unconverged points return NaN.
- **Cross-repo follow-through.** reprojax's own refinement is turned off once the inverse is exact (Stage 3 reprojax item).

**Ordering.** Astra preferred near-pole `atan2` first and Fable PyTree first; `atan2` is independent of the others, so this does not matter. Both agree that the PyTree fix precedes the CD check, and that Horner precedes the SIP inverse.

**Tolerances.** Keep 1e-6 px for fp64; fp32 limits come from measured caps (about 2.9e-4 px for the forward pair), not from hand-picked targets. Tightening to 1e-8 px waits for dense, compiled, multi-backend evidence.

#### The bare-`TanJax` case the item 8 wording misses

With x64 off, `TanJax` is 85.75 mas off on an *ordinary* field (vs 2.3e-7 mas with x64 on) and
100 mas on the L2 header. The cause is `WCSBase.__init__`'s `dtype=float`: it asks for f64,
gets f32, and the celestial↔native rotation is the one step that needs f64 — so this is the
precision design's central claim failing silently. The constructor accepts an f32 request but
silently substitutes an *insufficient* precision, which is worse than either an error or
honest f32. Item 8 covers `Reprojector(f64)` and explicit Mixed constructors; it should also
cover plain `TanJax`/`SinJax` under x64 off: either raise, or keep f32 and document the
envelope. The recommendation is to raise on bare JAX classes too, since their contract today
(rotation in f64) cannot be met — and to let `Reprojector` remain the documented f32 path.

#### Two corrections to the SIP inverse item

Both come from running the plan's own algorithm on the plan's own grids. The acceptance target
(1e-6 px, `tests/accuracy_reference.py`) drives the step budget, so this matters.

**Default step count 3 is one short.** With an AP/BP seed, Newton converges as 2.0e-2, 5.1e-4,
1.3e-5, 3.4e-7, 8.6e-9, 2.2e-10 px (steps 1–6) on the full 2040² L2 detector. Three steps miss
1e-6 by 13×; **four steps pass at 3.4e-7 and the real pair at 5.1e-8**. Set the default to 5,
which keeps a 100× margin (8.6e-9 and 1.1e-9) for 1.5 ms extra at 1201².

**The identity seed needs 6–8 steps.** With A/B and no AP/BP, converging from `(U, V)` gives
33, 0.84, 2.4e-2, 6.1e-4, 1.6e-5, 4.0e-7 px — so four steps land at 6e-4, which the 1e-6 target
rejects on a full detector (the A/B-only regression case is a 100 px field and passes early).
Seed instead from the linearised one-step `(U - f(U, V), V - g(U, V))`: 0.54, 1.1e-2, 2.7e-4,
7.0e-6, 1.8e-7 px, i.e. it reaches budget by step 5. Seed order: AP/BP if present, else the
linearised A/B one-step, never the identity.

**Cost is not a constraint.** A full inverse costs 4.5 ms at 1201² (3 steps) and 8.4 ms (6
steps) under `jit`; one forward polynomial is 0.21 ms. The extra steps are affordable.

**One prototype number does not reproduce as stated.** "Two Newton steps give 3.1e-11 px on the
L2 inverse" is 5.1e-4 px on the 33 × 33 full-detector grid, and 4.0e-5 px on a ±16 px patch.
The step counts above come from `accuracy_reference.py`'s own sampling, so use those.

**The pair is f32-limited, not step-limited.** Forward f32 is 2.4e-4 px from step 3 onward and
does not improve with more steps; the regenerated cap is ~2.9e-4, so the margin is 1.2×, not
10×. Do not tighten the f32 cap later without new evidence.

#### Notes that change the work slightly

- **`CAR` is a rejection test, not an accuracy test.** Gnomonic and CAR agree to 0.3″ over a
  1201² field at 6″/px, so a dense-grid comparison cannot catch the loader mapping one to the
  other. Rejecting the `CTYPE` is the only defence, which is what item 2 already does.
- **Item 3 owns 4 of the 8 near-pole `xfail`s; the other 4 are the same numbers on the JAX
  path.** At x64 on, JAX and NumPy agree to 2.9e-9 mas near the pole, so one fix flips all 8.
  Separately: with x64 off, `TanJax` is 85 mas off even on an ordinary field — an x64-policy
  symptom (item 8), not a near-pole one, and not currently covered by a test.
- **A f32-representable `CD` can have a zero f32 determinant.** `[[1e-25, 0], [0, 1e-25]]` has
  representable entries but `det = 0` in f32, so "check the determinant after casting", as item
  5 says, has to mean the cast matrix, not the fp64 one.
- **`benchmarks/benchmark_sip.py` does not exist**; item 6 creates it. `benchmark_accuracy.py`
  has no `--write-baselines`-adjacent bookkeeping for the pair caps beyond `PAIR_EXACT`.
- **`tests/test_wcs_json.py:115` is the only 5e-2 tolerance in the suite** and it is the SIP
  inverse round trip, so item 7 is the only item that can tighten it.
