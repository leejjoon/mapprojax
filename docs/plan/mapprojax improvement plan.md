# mapprojax improvement plan

Nov 1, 2026 · @이재준 · revised after a two-reviewer committee review (Claude Opus 5.5, Codex gpt-5.6-sol) of the Oct 31 draft

## Where it stands

mapprojax v0.2.0 is a ~1,200-line WCS core: two projections (TAN, SIN), SIP distortion, NumPy and JAX classes built from shared mixins, PyTree registration, the fp64-free `Reprojector`, and the offset-form `unproj_offset`/`proj_offset` APIs. 89 tests pass. It has no README, no CI, no release, and 0 stars.

The Oct 31 draft overstated two things and missed several bugs:

- **Precision.** "fp64-grade astrometry at fp32 cost" rests on a 200×200 round trip (7.6e-6 px). At realistic image sizes the measured errors are 1.9e-3 px for JAX Mixed and 2.6e-3 px for `Reprojector` f32, up to 8.4e-3 px for a cross-field pair at 0.05″/px (`docs/benchmarks/precision_results.md`). An fp32 pixel coordinate near 4096 has a spacing of 4.9e-4 px, so no fp32 path can reach the round-trip figure in absolute terms. The `reproject.py` docstring (~1e-4 px) and DEVELOPER.md (1e-3 to 1e-2 px) disagree with each other and with the measurements.
- **Correctness.** Four bugs return wrong answers or crash today; see Stage 2. The self-round-trip tests in `tests/test_projections.py` cannot catch them.

## Decisions

1. **mapprojax is JAX-first.** One class per projection, registered as a JAX PyTree. NumPy stays only where fp64 must live on the host: `crval` and the composition of the celestial↔native rotation. The NumPy `Tan`/`Sin` classes, the `*Array` variants (replaced by `vmap`), the `*Mixed` variants (precision becomes a static field) and the private per-projection reprojection legs all go. There is no PyPI release and the only downstream is reprojax, so the API break is cheapest now; no backward-compatibility aliases.
2. **mapprojax is the coordinate kernel; reprojax is the image tool.** mapprojax owns projections, distortions, rotations, precision policy and the source-pixel map with its validity mask. reprojax owns interpolation, flux handling, tiling and coadds. The Oct 31 draft's Phase 4 moves to reprojax.
3. **Compete on the precision design, not on projection count.** jax-galsim `GSFitsWCS` already covers TAN/TPV/TNX/SIP/STG/ZEA/ARC with iterative inversion. mapprojax's distinct contribution is the measured fp32/fp64 envelope, the offset form, and the fp64-free `Reprojector`. Add projections when real data asks for them.
4. **State numbers that survive scrutiny.** Lead with realistic-size errors (~2e-3 px at fp32, ~1e-11 px at fp64) and the plate-scale envelope, not the round-trip figure. Drop "fp64-grade".

## Milestone v0.3.0: a coordinate kernel you can trust

The stages are ordered so each one protects the next. The validation suite comes first because it is the safety net for the fixes and the restructure.

### Stage 1: independent validation

- [ ] Compare TAN, SIN and TAN-SIP against `astropy.wcs` (`all_pix2world` / `all_world2pix`) over dense grids. Replace self-round-trips as the main correctness check.
- [ ] Cover the edge cases: back hemisphere and the boundary of each projection's valid region, near-pole fields, RA wrap at 0/360, and SIP headers with A/B but no AP/BP. Seed with the wcslib `1904-66_*.fits` test headers.
- [ ] Publish the max and RMS disagreement (mas and px) as a table in `docs/`, generated by a script so it can be regenerated.

### Stage 2: correctness fixes

Commit these before the restructure so they do not wait on it.

- [ ] **Projection domains.** TAN maps a point 179.99° from the reference to a mirrored valid pixel; SIN folds the back hemisphere onto the front (`projections.py:6`, `:19`). Return NaN or a mask where `xn <= 0` (TAN) and `xn < 0` (SIN), written with a double-`where` so gradients stay finite.
- [ ] **SIP inverse.** With A/B and no AP/BP, `foc_to_pix` silently applies zero correction (`sip.py:31-32`); the measured round-trip error was 1.6 px. Upstream reprojax's `_sip_refine.py` (AP/BP initial guess + fixed Gauss-Newton steps) and harden it: start from AP/BP when present and from the identity otherwise, use the exact A/B solve automatically when AP/BP is absent, and return the residual or a convergence flag. Differentiate through the unrolled iterations; use implicit (`custom_jvp`) gradients only together with a residual check, since they are only valid at a converged root.
- [ ] **x64 warning.** The import-time warning (`__init__.py:4-10`) fires for `Reprojector` f32 and offset users, who do not need x64. Remove it; warn or raise only when a path that needs fp64 (e.g. `matrix_precision="f64"`) is requested with x64 off.

### Stage 3: JAX-first restructure

Timebox this stage. If it overruns, ship v0.3.0 with a small internal factory that generates the existing classes from each mixin, keep the public names, and mark the API unstable before 1.0.

- [ ] One class per projection, using `jax.tree_util.register_dataclass` (no equinox/flax dependency). Precision mode is a static field; per-pixel work runs in fp32 or fp64 accordingly.
- [ ] Fix PyTree reconstruction as part of this: `tree_unflatten` must not call `__init__` (`jax_base.py:34`, `:48`). Today it recasts dtypes, rebuilds the rotation matrix on every unflatten, and crashes on non-array leaves (`jax.eval_shape(lambda w: w, wcs)` raises `TypeError`). `Reprojector` already uses the `__new__` pattern (`reproject.py:217-222`). Add regression tests for `jit`, `vmap`, `grad`, `eval_shape` and dtype preservation.
- [ ] Keep `crval` and rotation composition as an explicit host-side fp64 step (NumPy), separate from the device kernel. Replace `unproj_absolute`'s NumPy-only restriction with a free function such as `absolute_from_offset(offset, crval_f64)`.
- [ ] Derive the inverse CD matrix inside the trace (closed-form 2×2) rather than storing `cd_inv` as an independent leaf, which would break gradients with respect to `cd`.
- [ ] Replace `*Array` classes with documented `vmap` usage; let `Reprojector` take any projection without a private leg subclass.
- [ ] Serialization: keep `to_dict`/`from_dict` (JSON, tested). Remove the ASDF converter until it handles SIP and the new classes; it currently drops SIP, registers only NumPy classes and has no tests.
- [ ] Update reprojax to the new API in the same pass.

### Stage 4: the kernel's public surface

- [ ] **Pixel map with validity mask.** Given a target shape, `Reprojector` returns source pixel coordinates plus a mask combining the projection domain and the source footprint. Every resampler needs this and only mapprojax knows the domains.
- [ ] **Gradient tests.** `jax.test_util.check_grads` with respect to `crpix`, `cd`, `crval` and SIP `a`/`b`, for each projection, at several field positions, in fp64 first and then with documented fp32 tolerances. A package sold as differentiable must verify this before release.
- [ ] **Differentiability table.** Which parameters are differentiable in which precision mode, including `Reprojector`'s host-side `crval` composition.

### Stage 5: docs and release

- [ ] Reconcile the precision numbers across the `reproject.py` docstring, DEVELOPER.md and `precision_results.md`, using realistic-size figures. Link the existing plate-scale envelope tables rather than producing new ones.
- [ ] Fix `docs/user_manual.md`: remove the nonexistent `to_bytes`/`from_bytes`, remove the ASDF recommendation, and rewrite examples for the JAX-first API.
- [ ] README built from `user_manual.md` and the DEVELOPER.md decision tree: what mapprojax is (coordinate kernel), what it is not (header parsing and general pix↔sky stay in astropy; image resampling is reprojax), the precision table, and the comparison with jax-galsim, dfreproject and astropy `reproject`. `pyproject.toml` already points at the missing README.
- [ ] State conventions once: 0-based pixels, `crval` in degrees, `proj`/`unproj` in radians, (lon, lat) order, and behaviour outside each projection's domain.
- [ ] Mark `fo64_report_and_plan.md` as implemented (its header still says "not started") and move it and `GEMINI.md` into `docs/notes/`. Add `*.fits` and `*.tgz` to `.gitignore` and clean scratch scripts out of the root.
- [ ] Rerun `benchmark_precision.py` on Strix Halo: the committed results predate the script's rewrite and lack the `Reprojector` columns and accuracy section.
- [ ] CI on GitHub Actions: one full job with x64 on, plus a separate-process x64-off smoke job covering import without warning, `Reprojector` f32, the offset APIs and no fp64 in the jaxpr. The tests toggle x64 themselves, so a full on/off matrix would mostly fail for expected reasons.
- [ ] Packaging: set `requires-python` and the JAX floor to what CI tests (the rocm extra already needs Python 3.12); add LICENSE; verify a clean wheel install.
- [ ] GitHub description and topics; tag v0.3.0; publish to PyPI.

## After v0.3.0

| Item | Why | Notes |

| `from_astropy(wcs)` | Lets users and reprojax pass astropy WCS objects directly | Accept TAN/SIN(+SIP), normalise CD/PC+CDELT through astropy, refuse everything else clearly. `to_header` later |

## Cut or deferred

- **Image resampling in mapprojax** (`reproject_interp`, flux-conserving variant, tiling, coadd): belongs in reprojax. When it is built there, note that JAX `map_coordinates` supports only order 0 and 1, and that Jacobian-scaled interpolation is not flux-conserving under downsampling (use adaptive anti-aliasing or drizzle).
- **Array-API backend inference and PyTorch/CuPy support**: works against the host-fp64 / device-fp32 split; dfreproject already serves PyTorch users.
- **equinox / flax**: `register_dataclass` covers the need without a dependency.
- **CAR, AIT, MOL; LONPOLE/LATPOLE**: needed only for all-sky maps, an audience not targeted yet. The default LONPOLE is already encoded for zenithal projections; general support must reproduce WCSLIB's defaults and ambiguity rules, not just a three-angle rotation.
- **`-TAB`, D2IM lookup distortions**: defer unless a user asks.
- **Horner evaluation for SIP**: the `0.0 ** 0` concern does not apply (integer powers give 1 and finite gradients); revisit only if profiling shows it matters.

## Risks

- **Bus factor of one.** Let the SPHEREx workload through reprojax set priorities rather than hypothetical users.
- **The restructure can stall the release.** Mitigated by the timebox and the factory fallback in Stage 3.
- **Precision claims are the trust signal.** Every number in the README must trace to a script in `benchmarks/` that a reader can rerun.
